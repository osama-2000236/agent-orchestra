# Evidence behind this update

These observations come from one owner-authorized Windows application review on 10–11 October 2026. They inform narrow workflow changes, not a cross-model benchmark. Private project data, signing keys and raw session logs are excluded.

| Observation | Judgment and limit |
| --- | --- |
| A first independent source review found no introduced defects; the next accounting lifecycle review found dispatch/invoice mapping, repeated return-line identity and free-text receipt attribution defects. A fix-only review found a legacy optional-array crash. | Review joins and supported legacy shapes after section passes. “No findings” is not proof; author fixes still need focused independent review. Native reviewer billing data was unavailable. |
| New regressions initially failed for unsupported fixture references and a missing seed ledger rather than the claimed defect. Corrected fixtures then reproduced the monetary failures against a pinned pre-fix engine. | Record the exact red failure and distinguish setup errors from defect-first evidence. Do not score a model against harness errors. |
| A synthetic valid 100,000-movement close completed in about 0.3 s, with pre/post validation. A report computation improved from about 1.2 s to about 1 ms with identical rows. | Measure representative computation and equivalence; these timings do not establish whole-screen or production performance. |
| Haiku 5.5 reviewed bilingual wording, and its clarity suggestions were applied. | A narrow wording worker is useful and cheaply checked; it does not certify layout, accessibility or accounting behavior. |
| A later Claude CLI orchestration launched two named Haiku read-only design workers. The aggregate result reported success after 79.1 s, four parent turns, attested `claude-haiku-5-5`, list-price total `$0.04606059`. Worker tools were Read/Grep/Glob; two useful UI-flow gaps were reported. A skill path was wrong and a large design file read was truncated. | Resolve actual skill paths and give focused artifacts/sections first. Distinguish source suggestions from runtime checks. Aggregate parent/child token and dollar semantics were not reconciled with an invoice, so no model-price optimum or live UI verdict is inferred. |
| Haiku 5.5 low-effort branding worker completed in 13.1 s and identified a misleading live Sponsors claim. JSON metadata reported `costBasis:list`, `$0.00837682`. It proposed `ai-review-orchestra`, with a compatibility-preserving skill name. | Use a small design worker for naming/presentation; API-equivalent cost is not actual subscription billing and a single trial is not a universal default. Availability was checked before publication. |
| The original router used guessed cost weights, transferred historical alias/unknown-effort rows, and called three checked claims “proven”. | Remove invented cost comparisons, partition model/effort evidence, disclose sparse samples and count missed defects separately. Policy thresholds remain explicit heuristics pending complete-task evaluation. |
| A public GitHub GraphQL query of the authenticated owner returned `sponsorsListing:null` and the repository's resolved `fundingLinks:[]` before this update. A pre-existing FUNDING.yml named the owner. | A funding configuration is not an active payment listing. Publish pending activation truthfully; financial onboarding cannot be completed from public repository credentials. |
| A CLI resume returned `is_error:true` and a weekly-limit message while `subtype` still said `success`. A worker had already made partial edits, and a read-only reviewer incorrectly expected a deliberately unavailable shell tool. | Inspect error flags and artifacts independently of subtype/exit code; preserve partial work and keep verification with the lead. Quota/tool failures do not establish poor model reasoning. Continue other sections without silently substituting the requested design model. |
| Initial file discovery omitted hidden paths and missed the installed system `review-agent` skill. A corrected hidden-file inventory found it before publication. | Include hidden skill roots when a named skill appears missing. Preserve default read-only independent review while adding explicitly requested whole-app/coordinating modes. |

Proposed defaults are provisional. Re-evaluate after representative complete-task samples, including lead verification, retries and missed defects. Keep the lesson's scope: one cheap wording/design source pass did not establish low-cost accounting implementation or exhaustive application quality.
